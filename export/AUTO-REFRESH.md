# BOTA coordination auto-refresh

`python3 tools/auto-refresh-coordination.py --once` is the automation-ready entrypoint. It runs one bounded, read-only coordination pass and writes `export/coordination-auto-refresh.json` with before/after counts, exact peer manifest hashes, every validator command and exit code, and `ok`.

Default mode is also bounded: 10 minutes, 10 second poll. It can be configured with `--minutes` and `--poll-seconds`. The loop is non-destructive and writes only BOTA export artifacts.

## Trigger

The runner hashes these peer files/directories before each pass:

- hy3d: `output/content-for-bota.json`, `output/content-demand-v2.json`, `output/generation-status.json`, `output/studio-recovery-watch.json`, `output/spawn-cdn-probes.json`
- wscheppity: `.local/extraction-manifest.json`, `.local/cdn/manifest.json`, `.local/cdn/manifest-all.json`, `.local/cdn/http/*`
- extra: `.local/extraction-manifest.json`, `.local/extraction-contract.json` when present, `.local/cdn/manifest.json`, `.local/cdn/manifest-all.json`, `.local/cdn/http/*`
- oscraft: `scenarios/bota/IDENTIFIERS.md`, `cross-contract-snapshot.json`, `bota_ui.json`

If any hash differs from the previous record, `--once` rebuilds `rule-demand.json` / `.tsv`, `content-request-queue.json` / `.tsv`, and `spawn-extraction-gaps.json` with the existing v2 builders, then refreshes deterministic engine provenance, hashes and status. It then runs the coordination, demand, queue, decision-packet, engine, apply-mechanism, fullname live-integration and consolidated pipeline validators. If no peer hash changed, it proves the current state with the focused validators and status validator.

`extra` is a first-class extraction peer: 78 CDN names from `/workspace/extra/.local/cdn/manifest-all.json` appear in `spawn-extraction-gaps.json` with `peer: extra`, exact evidence paths, and `nextActor: extra`. Its `/workspace/extra/.local/extraction-contract.json` is recorded as `UNAVAILABLE` when absent; missing peer paths are never fabricated.

## Strict no-promotion rule

The runner never applies a recommendation, never changes a canonical engine value, and never creates `export/engine-resolved/`. `owner-decision` and `intentionally-open` rows keep `do_not_promote: true`. The 425 decision-gated null fields, 27 gallery images, 26 active heroes, `003` image-only Reserve, Receipt/Repost/Camera chains and all creative text are preserved. The runner does not write to hy3d, wscheppity, extra, oscraft, gmweb or bitvoice.

## Safety proof

`python3 tools/validate-auto-refresh.py` re-runs every validator named in the record, reconciles live demand/coordination/queue counts, checks no orphan queue row, no active retired/reserve/old-slug key, canonical engine immutability, SHA-256 coverage, `STALE=false`, gated rows, absent `export/engine-resolved/`, and that peer files were not modified by BOTA. A peer changing its own files after a pass is reported as a live change requiring the next auto-refresh, not as a false success.

The owner dashboard and actor backlog are generated by `python3 tools/build-progress-dashboard.py` and validated by `python3 tools/validate-progress-dashboard.py`. Run `auto-refresh-coordination.py --once` after rebuilding them so hashes/status include the new artifacts.
